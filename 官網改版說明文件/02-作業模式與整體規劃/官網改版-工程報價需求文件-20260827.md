## 1. 背景與範圍界定

1. 客戶（AQUASKY）委由**原網站建置工程師**進行本次改版，並建置 CMS 後台，讓客戶端可自行維護內容；CMS 為工程師自建系統（非 WordPress）。
2. **改版範圍：僅 LQCOL PLUS 系列頁一頁**（https://aquaskyplus.com/en/LQCOL-PLUS），其他頁面不動。
3. **語系範圍：僅英文版**，其他語系不動。
4. **主機：沿用現行主機**；網站前方有 Cloudflare，DNS／Proxy 設定需保留。
5. 網站內容需同時服務「人」與「AI 搜尋引擎」，因此對 HTML 語意結構與結構化資料有明確要求（詳第 5 節）。
6. 網站上線後，另有一層 Cloudflare Worker（由梵亞維運）會在邊緣端補結構化資料；**上線排程需與梵亞協調同步調整**。

## 3. 範圍 B — CMS 後台

| # | 需求 | 說明 |
|---|------|------|
| B1 | 區塊式內容編輯 | 上述 A1–A7 各區塊可於後台編輯（文字、圖片、排序） |
| B2 | FAQ 模組 | 問／答成對管理，可增刪排序；前台輸出語意化 HTML |
| B3 | 規格表編輯 | 以列為單位編輯（型號、容量、尺寸…），前台輸出真實 `<table>`（`<th>`／`<td>` 正確） |
| B4 | 檔案管理 | PDF 上傳與連結管理（Downloads 區） |
| B5 | 圖片管理 | 上傳時必填 alt 替代文字欄位 |
| B6 | SEO 欄位 | 每頁獨立的 title、meta description、canonical 設定 |
| B7 | 結構化資料自動生成 | JSON-LD（Product、FAQPage、BreadcrumbList、Organization）由 CMS **依頁面實際內容自動產生**，不採人工貼 code。理由：現行手貼流程已造成頁面與結構化資料不一致（詳第 4 節） |
| B8 | FAQPage 輸出開關 | FAQ 模組可設定是否輸出 FAQPage JSON-LD（與邊緣層分工，由梵亞指定開或關） |

> B7 是本案重點需求：結構化資料的每一個欄位值，都必須與頁面可見內容同一來源，改一處即兩處同步。

## 5. 技術要求

1. **文字即文字**：所有內容文字（含表格、圖說、標題）一律為 HTML 文字，不得做成圖片。
2. **語意化標題**：每頁一個 `<h1>`（含品類關鍵字），區塊用 `<h2>`，層級不跳號。
3. **網址延續**：改版後保留現有網址結構；無法保留者提供完整 301 轉址對照表。
4. **canonical 與 sitemap**：每頁輸出 canonical；sitemap.xml 隨內容自動更新。
5. **多語系架構**：本次僅改英文版；保留現有語系切換，其他語系頁面不受影響。
6. **不得依 User-Agent 分流**：所有訪客（人與爬蟲）取得完全相同的 HTML。此為 Google 紅線，違反會遭處罰。
7. **禁止 robots 阻擋**：不得於 robots.txt 或 meta robots 阻擋搜尋與 AI 爬蟲（除後台路徑）。

## 6. 交付與驗收

| # | 驗收項目 | 標準 |
|---|----------|------|
| V1 | 文字可選取 | 頁面所有內容文字可於瀏覽器直接反白選取 |
| V2 | 標題結構 | 每頁單一 `<h1>`、`<h2>` 層級正確 |
| V3 | 結構化資料 | Google Rich Results Test 無 error；欄位值皆可對應頁面可見內容 |
| V4 | 表格 | 規格表為真實 `<table>` 且欄目正確 |
| V5 | 轉址 | 301 對照表全數生效（若網址有異動） |
| V6 | 測試站 | 上線前提供測試環境供梵亞驗證 |
| V7 | 上線協調 | 上線時間提前通知梵亞（邊緣層 Worker 需同步調整，未同步可能造成結構化資料重複或遺漏） |
